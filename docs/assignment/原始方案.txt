# 基于小型 GPT 的中文对联生成：可行性与实现方案

结论：这个选题可行，而且非常适合《具身智能基础》的“从零构建大模型”课程作业。

我建议将题目定为：

《基于 GPT 的中文对联生成模型设计、预训练与微调》

目标是训练一个小参数量的 GPT：用户输入上联，模型自动生成下联，并尽量满足对联的字数、词性、语义及声律要求。

它有三个明显优势：

1. 数据条件较好。 已经有超过70万副上下联配对的开源数据集。
2. 模型规模可以控制。 对联通常较短，不需要支持几千 Token 的长上下文，适合小型 Transformer。
3. 容易设计评估实验。 除了观察生成质量，还能定量评价字数匹配、重复率、平仄等指标。

但也有一个重要限制：生成字数正确的下联相对容易，生成语义工整、词性对应、平仄协调且富有文学意味的下联则困难得多。 所以我们应当把“完整训练流程”和“对联质量提升”分开作为两个层次的目标。

## 二、先明确：模型应该怎样生成下联？

我们不采用查找现成下联、根据词库拼接句子的方法，而是让 GPT 学习一个条件生成任务：

\\[ \boxed{P(\text{下联}\mid\text{上联})} \\]

例如：

用户输入 · 上联

## 春风又绿江南岸

自己训练的小型 GPT

根据上联逐字预测下联

目标输出 · 下联示例

## 秋月常明塞北天

这是用于说明生成任务的示例，并非实际训练结果，也不表示已经验证其全部传统格律。

模型将根据上联和已生成的下联前缀，预测下联的下一个字：

\\[ P\_\theta(y_t\mid x_1,\ldots,x_m,y_1,\ldots,y\_{t-1}) \\]

其中 \\(x\\) 表示上联，\\(y\\) 表示下联。

这种设计沿用 GPT 的 Decoder-only Transformer 架构，因此符合课程对 GPT 类模型的要求，而不必改用 Encoder-Decoder 模型。

# 三、推荐的实现流程

我建议采用小型 Decoder-only GPT + 通用中文预训练 + 对联监督微调 + 约束解码的技术路线。

这里的“约束解码”只是为了提高对联的形式正确率，真正的下联文字仍由 GPT 预测生成。

## 阶段 1：获取并处理对联数据

数据集原始结构类似：

```
train/
  in.txt     # 上联
  out.txt    # 下联

test/
  in.txt
  out.txt
```

例如，数据中一对上、下联可以表示为：

```
上联：竹报平安岁
下联：燕歌祥瑞春
```

模型微调需要把它们转换为一个完整的自回归训练序列：

```
<BOS><UP>竹报平安岁<DOWN>燕歌祥瑞春<EOS>
```

其中 `<UP>` 和 `<DOWN>` 是自定义的特殊 Token，用来区分上联和下联。

数据清洗必须先于训练。主要工作是清除重复样本、异常字符、字数不匹配的上下联，并处理标点。还要检查相同上联对应不同下联的情况，因为一副上联可能有多个合理答案，不能简单把不同下联视为错误数据。

特别注意数据泄漏： 同一上联及其高度相似的变体，应尽量分配到同一个数据划分中，不能让训练集和测试集出现重复或几乎相同的题目。

第一版建议先用五言、七言等短对联跑通完整流程，之后再逐渐扩展到更长的句式。开源数据集数量足够大，但数据质量仍需要实际统计和筛选。

## 阶段 2：实现适合中文的 Tokenizer

课程参考的 GPT 教学项目主要使用英文 BPE Tokenizer。但对联有一个特点：字数和字位对应非常重要。

因此，对这个任务，我建议第一版采用字符级 Tokenization。

例如：

```
上联：春 风 又 绿 江 南 岸
Token： [31, 75, 82, 106, 43, 58, 206]
```

每个汉字对应一个 Token；实际编号由训练集生成的词表决定。

优点是方便统计上下联的字数、在生成时控制长度，也减少了分词边界对对仗结构的影响。

初始可以考虑约 6000—10000 个字符及特殊 Token 构成的词表。具体大小要根据训练数据统计确定，并处理未登录字。

## 阶段 3：搭建小型 GPT

没有必要使用 GPT-2 原版1亿以上参数规模。

建议先采用下面的实验配置：

| 参数             | 初始建议                     |
| -------------- | ------------------------ |
| 模型结构           | Decoder-only Transformer |
| Transformer 层数 | 4—6 层                    |
| 隐藏维度           | 256—384                  |
| 注意力头数          | 4—6                      |
| 最大序列长度         | 64—96 Token              |
| Tokenizer      | 中文字符级                    |
| 参数量            | 约500万—1500万级             |
| 框架             | PyTorch                  |

这是一套待实验验证的起始配置，不是已经证实的最佳配置。

我们希望在有限显存和训练时间内，先得到具备基本语言生成能力的模型，再通过微调使它学习对联结构。

其中 GPT 必须体现课程要求的核心机制：

- Token Embedding 与位置编码。
- 带因果掩码的多头自注意力。
- 前馈神经网络、残差连接和层归一化。
- 下一 Token 预测与自回归生成。

对于这个选题，不推荐直接采用 BERT 或标准 Encoder-Decoder 作为主模型。它们也能生成对联，但会偏离本次构建 GPT 类模型的要求。

## 阶段 4：模型预训练

这是课程评分的重要部分，也是真正需要仔细设计的环节。

我们可以用通用中文语料进行预训练。具体数据集还需要单独选择，优先考虑来源明确、允许用于训练的中文文学及通用文本数据。

此时不要求模型学会对对子，只要求它学习基础的中文语言规律。

训练任务仍然是：

\\[ \mathcal L\_{\mathrm{pretrain}} =-\sum_t\log P\_\theta(x_t\mid x\_{\<t}) \\]

完成后，应保存基础模型权重、训练与验证损失曲线，并进行简短文本续写测试。

这里最大的风险是预训练不充分。 一个千万元素级别的小模型即使能学习语言统计规律，也不保证生成自然流畅的中文。

所以建议采用分阶段训练：先用少量语料验证程序，再逐渐增加数据量。必要时可以使用训练集中的上联和下联文本作为额外的无标签领域语料，但不能把保留的测试集提前混入预训练。

## 阶段 5：对联监督微调

这是整个项目最有特点的部分。

假设一条训练样本是：

```
<UP>竹报平安岁<DOWN>燕歌祥瑞春<EOS>
```

GPT 在生成下联时，能够通过因果注意力看到上联以及此前已经生成的下联字符。

我们希望它在已知上联的条件下，最大化标准下联的生成概率：

\\[ \boxed{ \mathcal L\_{\mathrm{SFT}} =-\sum\_{t=1}^{n} \log P\_\theta(y_t\mid x,y\_{\<t}) } \\]

实际训练还应包括结束 Token 的预测。

这与预训练的区别在于：微调主要对下联及结束标记计算损失，上联作为输入条件，不作为需要生成的目标。

在代码实现中，可以把上联和分隔符对应的标签设置为 `-100`，使交叉熵损失忽略这些位置。

我建议先使用全参数微调，因为模型很小，不必一开始就引入 LoRA。待完整流程成功后，再根据显存占用和实验需要考虑其他策略。

## 阶段 6：推理与对联约束

训练完成后，只需要输入：

```
<UP>竹报平安岁<DOWN>
```

GPT 就会逐字生成下联。

但普通自回归生成可能出现上下联字数不一致、重复字符过多等情况。

可以将推理设计为两个版本。

| 推理方式      | 处理方法                | 作用        |
| --------- | ------------------- | --------- |
| 原始 GPT 推理 | 直接按概率生成，直至结束标记或长度上限 | 检查模型本身的能力 |
| 约束 GPT 推理 | 控制下联字数、排除明显不合法输出    | 提高实际使用效果  |

优先加入的是字数约束，因为它最简单且比较可靠。

例如输入七字上联，就要求生成七字下联。Beam Search 或 Top-k Sampling 可以用于生成多个候选答案。

平仄约束可以作为后续扩展。需要注意，普通话拼音声调不完全等同于传统诗词使用的平仄体系，还可能受到多音字和古今音差异影响，不能直接认为拼音四声判断就是完整的对联格律判断。

# 四、如何判断模型是否真的学会了对对子？

这是我认为本项目最值得认真设计的部分。

对联生成不同于普通文本分类，同一个上联可能有很多正确下联，所以不能仅仅比较模型输出与数据集中标准答案是否完全相同。

建议分三个层次进行评价。

### 1. 形式正确性

这些指标最容易自动统计。

| 指标       | 测量内容             | 评价意义     |
| -------- | ---------------- | -------- |
| 字数匹配率    | 上下联的汉字数是否相等      | 基础形式要求   |
| 字符重复情况   | 是否出现异常重复或简单照抄上联  | 生成合理性    |
| 末字平仄符合率  | 在选定的声律标准下判断上下联末字 | 部分格律要求   |
| 字符级 BLEU | 与参考下联的局部字词重合程度   | 辅助评价生成结果 |

其中，字数匹配率要分别报告“原始生成”和“约束生成”的结果，否则会把解码规则的效果误认为模型学到了字数对应关系。

### 2. 语言与对仗质量

这部分更难完全自动化。

建议抽取固定数量的测试上联，人工盲评以下四个维度：

- 词性、词组结构是否对应。
- 上下联语义是否关联且协调。
- 是否满足基本声律要求。
- 语言是否自然，是否具有一定文学美感。

可以采用1—5分量表。也可以把句法分析器和拼音工具作为辅助，但古典汉语的自动分词和词性识别容易出错，不能把工具输出直接视为绝对标准。

### 3. 最有价值的对比实验

建议至少训练并比较三种模型：

| 实验组 | 训练方式             | 要验证的问题         |
| --- | ---------------- | -------------- |
| A   | 从随机初始化直接使用对联数据训练 | 只有监督数据能学到什么？   |
| B   | 通用中文预训练 → 对联微调   | 预训练是否提升下联生成质量？ |
| C   | 模型 B + 约束解码      | 形式规则是否进一步改善效果？ |

其中 A 与 B 应采用相同的模型结构、Tokenizer 和微调数据；尽量保持微调设置一致，才能更清楚地分析预训练的贡献。

C 则不需要额外训练，主要用于分析解码方法的作用。

最终既可以展示训练损失和测试指标，也可以在相同上联上展示三个版本的实际下联，讨论各自优缺点。

这个设计与课程要求非常契合，因为它不仅展示了最终成果，还能解释预训练、微调和推理策略分别解决了什么问题。

数据获取

小型 GPT 搭建

可行性高

可以直接以课程给出的 PyTorch 工程为基础，重点修改中文 Tokenizer、模型配置和数据加载部分。

预训练和微调

可行，但需试验

千万级参数模型能够进行单机训练实验，但最终质量受语料规模、显存、训练步数和模型容量影响。不能只凭数据集有70万副对联就保证生成效果。

生成高质量对联

主要难点

对仗不仅是字数相同，还涉及结构、语义、声律。建议将基本对联生成作为必达目标，把严格格律和文学质量作为提升目标。

## 六、我建议的项目开发顺序

不建议一开始就用全部数据训练完整模型。更稳妥的方式是分四轮迭代：

1. 第一轮：最小系统验证

   使用少量数据测试中文分词、GPT 前向与反向传播、权重保存和加载、下联生成代码。此时不要求生成质量。
2. 第二轮：完成预训练

   使用选定的中文语料进行自回归预训练，记录 Loss 和生成样例，保存基础模型。
3. 第三轮：完成对联微调

   使用经过清洗的上下联配对训练，先验证模型能够生成与上联相关的短下联，再逐步增加数据和训练规模。
4. 第四轮：评估和应用展示

   比较 A、B、C 三种实验设置，完成自动指标与人工评价，最后提供一个命令行交互程序或简单网页。

源代码可以组织成以下结构，便于和实验报告对应：

```
couplet_gpt/
├── configs/             # 模型与训练配置
├── data/
│   ├── raw/             # 原始数据
│   └── processed/       # 清洗、划分后的数据
├── model/
│   ├── attention.py     # 多头因果注意力
│   └── gpt.py           # GPT网络结构
├── tokenizer.py         # 中文字符级Tokenizer
├── prepare_data.py      # 数据预处理
├── pretrain.py          # 预训练
├── finetune.py          # 对联监督微调
├── generate.py          # 下联生成
├── evaluate.py          # 评估程序
├── checkpoints/         # 保存模型权重
└── README.md            # 环境与复现说明
```

## 七、最终建议

我建议把项目的验收目标划分为两级。

基本目标（确保完成课程作业）： 自己搭建 GPT、完成中文预训练、对联微调、加载权重输入上联并生成下联，提供损失曲线和模型前后对比。

进阶目标（提高项目质量）： 在测试集中实现较高的字数匹配率，并在词语对应、语义协调与文学质量上取得可观察的改进，同时利用消融实验解释改进的来源。

下一步最应该做的不是训练，而是数据分析和计算预算评估。 先下载对联数据集，统计上下联长度分布、字符词表规模、重复率、异常样本比例，并根据可用显存确定 GPT 参数量与最大上下文长度。

这些统计结果将直接决定后续模型配置、Tokenizer、训练效率以及评估方案，比直接选一个网络结构开始训练更可靠。

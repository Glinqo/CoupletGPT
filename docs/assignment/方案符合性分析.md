## 必须落实的调整

### 1. 把预训练与微调做成可辨认的两个阶段

建议保留“中文连续文本下一字预测 → 上联到下联监督微调”的路线。这是展示课程要求最直观的方式。

- 预训练：从随机参数开始，对连续中文文本做下一 Token 预测，保存基础模型、配置、Tokenizer 和曲线。
- 微调：加载同一基础模型和词表，对配对任务训练，主要计算下联及 EOS 的损失，保存微调模型。
- 展示：分别提供预训练后的续写，以及微调前后同一上联的下联生成结果。

通用中文预训练是原方案的选择，PDF 本身没有限定必须采用通用语料。必要时可以采用训练划分内的领域文本做自回归预训练，但必须清楚说明两阶段目标和数据差异，不能仅把一段连续训练改名成“预训练”和“微调”。不应以调用现成模型 API 或仅微调公开权重替代本项目的从零训练主线。

### 2. 确定数据和计算预算

先明确可用设备和显存，再决定模型与数据规模。原方案的层数、宽度和参数量只是候选值，不是实测结论，不能据此承诺训练时长或效果。

建议起步配置为 4 层、隐藏维度 256、4 个注意力头、上下文 64；实际词表统计后再计算参数量。Embedding 与输出层是否共享权重会明显影响参数量，应明确记录。

上下文长度必须容纳 BOS、上联、分隔符、下联和 EOS 的完整序列。先筛选五言、七言样本有利于控制难度，但属于实现取舍。

语料来源、版本、可用性、使用条件与清洗后数据量需另行核验。不能将原方案提到的“超过 70 万副”直接写成最终使用样本数。

### 3. 防止测试信息进入训练

先去重并按上联分组划分训练、验证和测试，再构建词表与预训练语料。训练集构建词表，明确 UNK、PAD、BOS、EOS、UP、DOWN 的处理。若补充预训练语料，排查其与保留测试对联的重叠，并记录排查方法和局限。

微调应核对自回归标签右移：不能只机械地把某段标签置为 -100，还要确保预测第一个下联字和 EOS 的位置均被正确监督。PAD 不计入损失。

### 4. 把报告作为主要交付物

PDF 明确：项目报告是评分依据，源码非必需，但鼓励整理后提交；使用开源资料和代码是允许的，需详细列出网址。应说明参考了哪些模块、修改了哪些部分、实际独立完成哪些训练和评估工作。

报告最后必须补充个人成果、收获、体会和评价。不能用未来计划代替实际实验结果。

原始生成与长度约束生成应分别报告。长度约束下达到字数一致主要说明解码规则有效，不能单独证明模型学会对仗。平仄指标若使用现代普通话声调，应明确标为近似评价，不能宣称覆盖传统格律。A/B 对比还应报告额外预训练所用数据和计算量，不能将提升解释为完全等预算下的结论。
